# GCSE operating guide

This guide turns the framework into repeatable workflows. Each workflow preserves the four-part structure and returns a copy-ready prompt rather than performing the prompt's task.

## Build a prompt

1. Capture the task, audience, intended tool, and available source.
2. Ask only for missing details that materially change the result.
3. Draft Goal, Context, Source, and Expectation.
4. Insert actionable placeholders for unavailable inputs.
5. Apply the safety and quality controls.
6. Return the prompt with brief usage guidance.

## Explain a prompt

1. Show what each GCSE section contributes.
2. Connect specific wording to the likely response.
3. Identify placeholders and how to customize them.
4. Explain the difference between Context and Source.
5. Avoid scoring unless a formal review was requested.

## Improve an existing prompt

1. Preserve the original intent.
2. Extract details already present.
3. Ask only for essential missing information.
4. Reorganize the request under the four headings.
5. Add source boundaries, output criteria, and useful placeholders.
6. Confirm that no unsupported requirement was introduced.

## Optimize for a tool

1. Confirm the tool and interaction point.
2. Preserve the task and source.
3. Use capabilities that are known to be available.
4. Adapt Expectation to the tool's useful output forms.
5. Avoid claims about unsupported access, automation, or integration.

## Validate a prompt

Check:

- Goal specificity and single-task focus;
- Context relevance;
- Source availability, scope, and priority;
- Expectation completeness;
- placeholder usability;
- fact and assumption boundaries;
- privacy and people-related safeguards;
- fit for the intended tool and audience; and
- copy-ready clarity.

Repair clear wording or structural issues without changing intent. Surface substantive ambiguity for a user decision.

## Reframe a sensitive request

1. Identify the legitimate business purpose.
2. Remove unnecessary sensitive inputs.
3. Substitute aggregated, de-identified, sanitized, fictional, or placeholder data.
4. Replace judgments about people with observable evidence and documented expectations.
5. Keep decisions and accountability with a person.
6. Return a safe GCSE prompt that still serves the legitimate goal.

## Curate reusable prompt collections

For each prompt pattern, maintain:

- a stable identifier and concise title;
- one primary task;
- intended audience and tool;
- source and output types;
- natural-language retrieval terms;
- a complete GCSE pattern;
- source traceability;
- lifecycle status and review date; and
- documented gaps or conflicts.

Merge duplicates only when their task, audience, source type, and expected output match. Preserve unique requirements and source references.

## Final response pattern

When delivering a completed prompt, use:

1. a brief description of what it will do;
2. the copy-ready GCSE prompt;
3. a short explanation of why the structure fits;
4. steps for completing placeholders and supplying sources; and
5. a reminder to verify accuracy, context, completeness, and sensitive information before use.
