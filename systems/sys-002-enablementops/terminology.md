# EnablementOps controlled terminology

## Approved hierarchy

`Operating system → Framework → Workflow → Playbook → Asset or template`

Standards, controls, schemas, automation, evidence, and measures may support any layer.

## Controlled definitions

| Term | Definition | Usage rule |
|---|---|---|
| EnablementOps | The operating system governing the full enablement lifecycle and the capabilities required for successful performance. | Use for the complete governed system, never as a synonym for a single framework. |
| EngagementOps | A separate, optional operating system governing audience awareness, activation, participation, campaigns, channels, and continuing engagement. | Activate only when defined engagement needs exist; do not make it mandatory for every EnablementOps initiative. |
| ReinforcementOps | The operating domain for spaced practice, nudges, reinforcement, and sustained behavior after initial enablement. | Treat as a distinct companion domain until separately registered and governed. |
| Operating system | An end-to-end governed model coordinating multiple frameworks, workflows, playbooks, standards, controls, assets, and evidence. | Register with a `SYS-###` ID. |
| Framework | Principles and decision structures that guide work. | Register with an `FW-###` ID; do not use for an end-to-end operating system. |
| Workflow | Ordered steps that move work from a defined trigger to an outcome. | Register with a `WF-###` ID. |
| Playbook | Reusable operating guidance combining roles, rules, judgment, examples, and exceptions. | Register with a `PB-###` ID. |
| Standard | A mandatory requirement or specification used to control quality or consistency. | Distinguish from recommendations. |
| Recommendation | Non-mandatory guidance selected through judgment. | Never present as a required control. |
| Adoption asset | An asset intended to help an audience begin or increase use of a capability. | State whether EnablementOps, EngagementOps, or both own its lifecycle. |
| Engagement asset | An asset intended to attract attention, prompt participation, or sustain audience interaction. | Govern through EngagementOps when that system is activated. |
| Workflow nudge | A contextual prompt embedded near the point of work. | Assign ownership and measurement explicitly. |
| Behavioral reinforcement system | A coordinated set of practice, reminders, feedback, and support intended to sustain behavior. | Do not reduce to a one-time communication or training asset. |

## Layer model

The approved operating layers are:

1. Source of Truth
2. EnablementOps
3. EngagementOps
4. ReinforcementOps

Community Operations, Measurement, and Governance operate alongside those layers as cross-cutting capabilities.

## Prohibited ambiguities

- Do not call EnablementOps a framework.
- Do not use EnablementOps and the L&D Operating System as interchangeable names.
- Do not classify LACE as the whole of EnablementOps; LACE is a component system focused on learning-asset creation.
- Do not merge EngagementOps into EnablementOps.
- Do not duplicate an authoritative rule across component documents without identifying its canonical source.
